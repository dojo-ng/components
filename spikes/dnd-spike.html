K7 — DnD engine spike: pragmatic-drag-and-drop vs an in-house pointer core

Two questions decide the @dojo-ng/dnd engine: (a) does drag work when the draggable items live INSIDE a shadow root (every Dojo NG component does), and (b) does it work on touch. Both sections below put their lists inside real custom-element shadow roots, matching how the board and list actually render. Watch the logs; a short verdict is written to each after you try a drag. To test touch, open your browser's device/responsive mode (or a real device) and repeat.

Section A — pragmatic-drag-and-drop (loaded from esm.sh, spike-only)

Expected per Atlassian issue #116 (still open): a draggable registered on an element inside a shadow root never fires onDragStart/onDrop, because native drag events retarget to the shadow host. If the log stays empty when you drag, that reproduces the blocker. (If the import 403s or fails, that's noted in the log — it's a CDN issue, not the point.)

Section B — in-house pointer-events core (no dependency)

The fallback design: pointerdown + setPointerCapture, a ghost that follows the pointer, hit-testing the pointer against the (shadow-internal) lane containers, a drop indicator, and pointerup computing the drop index. Pointer events unify mouse, touch, and pen, so this works across shadow roots and on touch by construction. Drag a card between the two lanes with the mouse, then again in touch/device mode.
